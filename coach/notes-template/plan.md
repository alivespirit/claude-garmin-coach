# Training plan

As of YYYY-MM-DD. Block N runs from YYYY-MM-DD to YYYY-MM-DD. The coach keeps this file in sync
with the Garmin calendar. Until it's filled in, the calendar is the plan.

## Why the plan looks like this

What the analysis before this block found (e.g. too much Z3, weak aerobic endurance), and the
decisions that followed:

1. **Easy runs stay easy:** HR ≤ … .
2. **Quality sessions:** which ones and why.
3. **Long run progression:** e.g. 16 → 18 → 20 km, then a shorter recovery week.
4. **Strength:** what each session is for.
5. **Volume:** … km/week, then a recovery week.

## Targets by workout type

- **Easy:** HR range …; no pace target.
- **Strides:** duration, pace, recovery (walk or jog).
- **Threshold:** pace … (… m/s in Garmin), HR ceiling … .
- **VO2:** pace …, expected HR at the end of a rep, recovery.
- **Long run:** HR range … .

## Tests

Planned tests (e.g. a 30-minute threshold test), their structure, how to read the result and
what to recalculate afterwards.

## Adjustment rules (agreed)

- **Long run:** distance flexibility, HR ceiling, what to do with extra kilometres.
- **Fueling on long runs:** when to take gels, how much to drink.
- **Threshold / VO2:** when to move target paces.
- **Heavy legs or low readiness:** what changes.
- **Unreliable GPS:** which screen fields and metrics to trust.
